# Write captions and triggers that separate concepts

[Table of contents](../README.md)

<!-- book-navigation:end -->

A caption tells the model which visible or audible relationships should be associated with text. It is not merely a filename description and it does not need to enumerate every pixel. The useful caption is specific enough to separate the target concept from its changing context, consistent enough to learn, and natural for the model family being trained.

This chapter explains the caption controls implemented by `DatasetConfig` in `toolkit/config_modules.py` and applied by `FileItemDTO.get_caption` in `toolkit/dataloader_mixins.py`. Use the [dataset settings reference](../reference/dataset.md) for exact types, defaults, and UI exposure.

## Choose what the caption should explain

Start from the learning goal in the [curation chapter](curation.md). Caption attributes that should remain controllable at inference time, and avoid repeatedly naming accidents that do not belong to the concept.

For a subject or object LoRA, a caption might identify the trigger and then describe pose, viewpoint, clothing, action, environment, lighting, and medium when those features vary. If every image says only the trigger, all recurring details are left bundled with it. If every caption repeats the same generic words, those words do not help distinguish one example from another.

For a style LoRA, describe the depicted content so the target style is the stable unexplained relationship. Captioning every image only as “in the target style” gives the model little textual evidence that a castle and a portrait are different content expressed through a shared rendering language.

For edit training, caption the requested transformation according to the model's expected instruction format. For video, describe meaningful subject, action, camera, and temporal behavior rather than listing every frame. For audio, identify the relevant voice, sound, performance, or acoustic condition without asserting properties that are not present.

Choose one caption form deliberately:

- Natural sentences preserve syntax and relationships. They should not be token-shuffled.
- Comma-separated tags make attributes explicit and can tolerate some reordering, but ambiguous fragments can lose who or what they modify.
- Short captions reduce annotation work but leave more correlations implicit. Detailed captions add control only when their details are accurate.

Use one vocabulary for the same recurring property. Resolve spelling, capitalization, aliases, and contradictory labels before training. Captions generated by another model are drafts: inspect them against the media, especially identity, count, left/right, text, action, and fine object details.

## Pair caption files and fallbacks correctly

For a folder dataset, a sidecar caption normally shares the media basename and uses the configured [`caption_ext`](../reference/dataset.md#dataset-caption-ext). ai-toolkit's engine fallback is `.txt`; a nonempty configured value without a leading dot is normalized by adding one, so `txt` becomes `.txt`. The Simple UI commonly writes `txt`.

Test a few complete pairs before a long run:

```text
dataset/
  frame-001.png
  frame-001.txt
  frame-002.webp
  frame-002.txt
```

An incorrect extension can leave items without their intended sidecars. It does not make an almost-matching name valid. Check case sensitivity on the training filesystem, hidden double extensions such as `image.png.txt.txt`, empty files, encoding problems, and stale captions left behind after media was renamed.

[`default_caption`](../reference/dataset.md#dataset-default-caption) supplies deterministic text when an item has no usable caption file or map entry. Use it when uncaptained media is intentional and genuinely shares one description. Do not use a broad fallback to hide missing annotations: the same weak or misleading caption repeated across many files can become a major training signal.

Before enabling variation controls, print or inspect the effective captions for a representative batch. The loader works with the resolved caption after fallback, trigger processing, dropout, and shuffling—not necessarily the sidecar text as it appears on disk.

## Place and test a trigger

A trigger is an activation phrase associated with the target concept. It is useful when the concept needs a compact name that is unlikely to be confused with an existing broad word. It is not mandatory for every style or behavior; the recipe and base model matter.

The process-level trigger can be overridden per dataset with [`trigger_word`](../reference/dataset.md#dataset-trigger-word). In ordinary non-regularization data, ai-toolkit replaces `[trigger]` and `[name]` placeholders with the resolved trigger. If the resolved trigger is absent, the current loader adds it at the beginning of the caption. Regularization data marked with `is_reg` does not receive that automatic insertion.

Use a stable phrase consistently. These are clear patterns:

```text
[trigger], portrait, side view, warm window light
a product photo of [trigger], on a wooden desk
```

Test the trigger in fixed-seed samples by comparing prompts with it, without it, and with surrounding attributes changed. A useful trigger activates the intended relationship without making the rest of the prompt inert. If it appears several times in a caption, remove the duplicates rather than expecting repetition to improve identity.

[`random_triggers`](../reference/dataset.md#dataset-random-triggers) can append alternate trigger strings. Use it only when alternate activation phrases are an explicit goal. A string is treated as a line-delimited file only when that path exists; a nonexistent string path remains a string, and downstream sampling can select individual characters. Prefer an explicit list, or verify the trigger file and keep `random_triggers_max` no larger than the resolved population.

## Use dropout deliberately

[`caption_dropout_rate`](../reference/dataset.md#dataset-caption-dropout-rate) is the probability of replacing the effective caption with an empty caption for an eligible item. A small amount can add unconditional behavior and reduce dependence on one exact phrasing. Too much weakens text alignment and may make a trigger unreliable.

[`token_dropout_rate`](../reference/dataset.md#dataset-token-dropout-rate) independently drops eligible comma-separated caption chunks. This can reduce dependence on every tag always appearing together, but it is poorly suited to prose because deleting one comma chunk can damage meaning. `keep_tokens` exempts the configured number of leading chunks from token dropout in the current dataloader.

Text-embedding caching treats the two dropout controls differently. Live token dropout is skipped while embeddings are cached, so `token_dropout_rate` does not create a new token subset on later training loads. Caption dropout remains active: cache preparation stores the normal embedding and, when `caption_dropout_rate` is positive, a cached blank embedding (or trigger-only dropout caption where applicable); each load can randomly select the dropout embedding at the configured rate. This preserves full-caption-versus-dropout variation without rerunning the text encoder, but it does not create arbitrary new caption variants. The caching boundaries and invalidation rules are developed in [performance and caching](../advanced/performance-and-caching.md).

Start with the recipe default, inspect effective captions, and change one dropout control at a time. A rate is a probability per eligible caption evaluation, not a promise that exactly that fraction of a small dataset will be dropped in every short interval.

## Shuffle only interchangeable tokens

[`shuffle_tokens`](../reference/dataset.md#dataset-shuffle-tokens) randomizes comma-separated caption chunks. It can reduce accidental reliance on tag order when the chunks are genuinely interchangeable:

```text
my_trigger, red jacket, outdoors, side view, soft light
```

Do not shuffle a sentence such as “a dog chasing a red ball behind a child.” Its order carries grammar and relationships. Also avoid comma chunks whose meaning depends on a neighboring chunk.

The current `toolkit/dataloader_mixins.py` path can shuffle once before trigger insertion and again afterward. `keep_tokens` protects leading chunks from token dropout, but it does not preserve their position through these full-list shuffles. When stable trigger placement matters, leave `shuffle_tokens` off instead of relying on a protected-prefix assumption.

With cached text embeddings, caption construction happens during cache preparation and the resulting embedding freezes that realized order. Shuffling is therefore not fresh augmentation on every later training step. Clear and rebuild the relevant text-embedding cache when changing caption content or caption-processing settings.

## Audit captions before training

Run a deterministic audit whenever the dataset version changes:

1. Verify every media-to-caption pairing and list every item using `default_caption`.
2. Search for empty, duplicated, contradictory, malformed, or unexpectedly long captions.
3. Count trigger occurrences and inspect captions where the trigger is absent or repeated.
4. Review attribute frequencies to find a label used only with one background, pose, speaker, or camera condition.
5. Preview effective captions with the intended dropout, trigger, and shuffle settings.
6. Save the caption files and audit report with the dataset version provenance.

For a diagnostic run, keep caption processing simple. Confirm that the baseline learns and responds to text before adding random triggers, token dropout, or shuffling. When a change helps one prompt but harms another, compare the same checkpoint cadence and fixed seeds, then decide whether the issue is caption content, trigger behavior, or training configuration.
